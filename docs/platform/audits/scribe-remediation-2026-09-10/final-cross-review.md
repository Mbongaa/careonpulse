Bounded local review, 2026-09-10. Reviewed current transcription adapters, server replay orchestration, note creation/edit/approval routes and atomic SQL, and demo/remote English and correction integration. No production writes, provider calls or full builds. The executable synthetic probe is `cross-review-probe.ts`; its output is `cross-review-probe.txt`.

## Findings discovered during review (subsequently remediated locally)

1. **P1 — Note model can undo C07 state grounding.** `agent.server.ts` `combineerSecties` accepts a model rewrite if it has at least one existing source number and does not match risk-polarity rules. Actual mocked `genereerVerslag` input with only `Ik heb hoofdpijn.` in segment 1 and a clean headache state accepts `Patiënt gebruikt lithium 900 mg en is allergisch voor penicilline.` citing `[1]`. The fabricated medication/allergy appears in editable `tekst`, with `vereistBehandelaar=false`. This is not prevented by state-version/transcript-version binding: those guarantees establish which input version was used, not whether the generated wording is grounded. Require canonical section/state-supported wording or keep unsupported rewrite out of an approvable prefilled section. Root notified with executed proof.

2. **P2 — Malformed report row escapes fallback.** `leesModelSecties` reads `record.id` without guarding a null/nonobject row. Actual mocked `genereerVerslag` with `secties:[null]` throws `Cannot read properties of null (reading 'id')`. Analysis speaker/correction parsers were hardened, but the report parser needs the same protection. Root notified with executed proof.

3. **P2, demo-only — Obsolete proposed task survives corrected source.** `wijzigSegmentLokaal` invalidates the state but retains existing tasks; `analyseerLokaal` only adds new tasks. Reproduce a doctor lab request, analyze, correct it to `Ik vraag geen bloedonderzoek aan.`, then reanalyze: state plan/actions disappear, but the previous proposed lab task remains actionable. Backend SQL already deletes proposed tasks on source correction while preserving clinician decisions. UI workstream notified to mirror this behavior and add a regression.

4. **P2, demo-only — Analysis reads beyond its reported batch cursor.** `analyseerLokaal` caps `nieuweSegmenten` at 40 but sends the entire transcript as `alle` to `deterministischeRonde`. The latter extracts all supplied segments and applies dictionary corrections only to the new batch. With `Ik gebruik sertaline 50 mg.` in segment 41, the first pass can store uncorrected `sertaline`; the next pass corrects to `sertraline`, while additive state retains the first invented medicine. Production orchestration supplies only prior context and the current batch. UI workstream notified to use that same bounded effective input; the synthetic probe exercises the exact two-round arguments.

### Remediation and final evidence

- Findings 1–2 were fixed in `agent.server.ts`. The report request now includes canonical section text. A report section is accepted only when its entire text matches canonical content under explicitly allowed formatting normalization and its complete source set matches existing canonical sources. Unsupported additions, omissions, dose/negation changes and malformed source sets retain the deterministic/manual section. Source markers in accepted output are rebuilt from the verified set. If no model section is accepted, output provenance is deterministic. Null/nonobject section rows are ignored safely.
- The maintained actual-agent suite `src/scripts/verify-scribe-clinical.ts` now has **120 passing checks**, including twelve final-report cases. It preserves a positive example of a verifiable formatting rewrite while rejecting the fabricated-medication proof, altered dosage, omitted allergy and changed negation. English rejection leaves every fallback section manual. The report prompt version is `careon-scribe-2026-09-10.2`.
- Domain verification remains **97 passed**, and the four-file scoped Biome check is clean. Results are in `clinical-verification.txt`, `clinical-domain-verification.txt`, and `clinical-biome.txt`.
- The UI workstream reported findings 3–4 fixed and tested in the actual demo store: correction removes only proposed tasks, approved clinician decisions survive, and the 41-segment case processes no future medication during the first batch and exactly one corrected sertraline row in the second. The backend already had the corresponding correction task cleanup. The UI workstream owns those tests; they were not rerun independently here.
- `cross-review-probe.txt` preserves the **pre-fix** counterexample output. Its direct two-round arguments intentionally represent the former incorrect demo callsite; the maintained demo-store regression tests cover the now-correct callsite.

Application and test files were frozen after these checks so the root workstream could begin final integration CI/build/browser verification. These local fixes do not imply production deployment.

## Confirmed integrations / no additional serious issue found in this bounded review

- OpenAI diarization construction omits the unsupported prompt and selects diarized output/chunking. English instructions are passed to supported non-diarizing OpenAI and Vertex requests. Vertex accepts only the configured EU target region and validates project/model/service-account shape. Public transcription failure messages omit parser/body contents; malformed recognized payloads fail instead of silently looking like successful transcription. This review did not validate live provider availability, contractual settings or residency configuration.
- Server correction-triggered state rewinding to zero feeds `heranalyseStartStaat` before the first replay batch. Later batches remain additive. `bewaarBehandelaarsfeiten` only restores explicit clinician-owned facts already seeded by the helper; no new preservation inconsistency was found.
- Note creation binds state revision and current transcript revision under the session lock, requires an up-to-date complete analysis and canonical sections, and prevents machine-filled mandatory clinical assessment sections.
- Atomic note edit/approval checks expected edit revision, source state revision, transcript revision, complete analysis, nonempty approved section text, required manual sections and acknowledged known gaps. The old revision-free approval function is revoked. These controls do not replace content grounding (finding 1).
- English deterministic reports preserve empty manual sections through creation and bulk approval; the demo passes session language and the backend enforces manual flags for deterministic/demo English notes.

This is an independent integration review and synthetic engineering evidence, not clinical certification or production acceptance.
